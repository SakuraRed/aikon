# 上色合同与反模式

这是 Aikon 的生产约束，适用于代码绘制与模型辅助绘制。它将已确认的造型和上色分别记录，使局部上色修正不会顺带改变主体。它不是原作者的 renderer 说明，也不修改[精简版源译文](prompts/source-short.zh-CN.md)或[完整版源译文](prompts/source-full.zh-CN.md)。

**当前覆盖**：[natural-gloss-v2](natural-gloss-v2.md)允许自然低频gradient、微弱眼缘gloss及顺形宽高光。以下反模式仍适用；旧纯色眼、默认零高光或过窄色差预算不能成为压平参考的理由。

## 先区分三个层次

- **Geometry**：外轮廓、可见脸域、发束分组、眼睛、饰件连接、裁切与遮挡关系。
- **Material**：哪些区域是同一发色、脸、布料或硬质饰件；来源确有双色时保留双色，不能将所有色差解释为光照。
- **Paint**：每个材料的底色、允许的平滑色调变化、阴影与高光。

用户认可整体而指出上色缺陷时，冻结对应 geometry 与身份特征，只替换 paint。认可整体不等于每条曲线或每个像素已经验收；未被认可的局部仍单独记录，不借上色任务偷偷重画。用户改正主体身份时，以最新指令更新主体证据，不能继续套用旧解释。

## 色场必须有可解释的来源

每个主要发束或材料面至少声明下列信息。可以存入当前设计文档或独立 JSON；字段是可移植的语义合同，不表示某个 helper 已经实现相同 schema。

| 项目 | 必须说明的内容 |
| --- | --- |
| `region_id` / `material_id` | 唯一名称与所属材料；边界来自几何形态，不来自位图自动量化 |
| `base_tone` | 明确颜色；同材料共用调色板，避免每个碎片另取一种近似色 |
| `base_field` | `solid`，或有明确方向、起止颜色与少量控制点的 `smooth_gradient` |
| `shadow` | 可为无；否则说明接收区域 `receiver`、遮挡来源或转折依据 `anchor`、层级、颜色与覆盖形状 |
| `highlight` | 默认无；必要时说明接收区域、宽阔受光面的依据、统一光向、范围与数量 |
| `geometry_lock` | 本次保留的轮廓、变换、眼位及前后关系；改动须在版本差异中单列 |

一条阴影应当能回答“哪一束盖在哪一束上，暗面落在哪里”，或“这是哪一个宽缓转面的背光侧”。不能只写 `shadow-3` 或“增加层次”。避免多个窄透明片堆出无依据色阶；一个二维连续受光场可以用少量宽linear/radial场合成，但仍需同一形体依据、完整可见域检查及实际视觉判断。不同材料本身的底色差不算同材料增加一档阴影。

底色默认不透明。需要柔和过渡时优先用区域内部确定性的平滑 gradient，并显式记录颜色插值方式与坐标空间；不依赖背景参与混色。允许的 gradient 表示一个连续的大尺度明暗变化，不表示噪声、颗粒、云纹、斑驳、喷枪光点或重复明暗波纹。眼睛保留完整暗色capsule语法；当前允许参考支持的微弱暗色gradient和一体细边光泽，不加入独立白点、虹膜或瞳孔。腮红保持简单淡色形状。

高光不是“每束发都画一个”。精简版以无需高光为默认；完整版只在确有帮助时保留整体一到两个主要大高光区域，不把数量上限按每个发束重复发放。白色饰件、原生异色发束不是高光。高光应顺着一个可解释的大形体，亮度、曲率、方向和视觉重心相容；数量合规仍可能不自然，必须实际查看。

## 可复核的反模式

| ID | 反模式与识别方法 | 为什么出错 | 修正与检查边界 |
| --- | --- | --- | --- |
| P01 | 发束内部出现云雾、脏色、细粒；离轮廓很远仍有不规则明暗起伏 | 位图纹理、滤镜或未经约束的叠色被当作形体 | 重建 solid 或简单 smooth gradient；检查区域内部残差，目视确认没有涂抹纹理 |
| P02 | 星形、多尖菱形、拼接三角亮斑悬在同一软发束中，找不到转面或遮挡依据 | 用局部亮片代替体积解释 | 删除无依据亮斑，必要时合并成顺形的大受光面；不能靠“高光数不超限”放行 |
| P03 | 一束内连续出现亮—暗—亮，或许多相近深浅碎片相互覆盖 | 自动量化、分层描摹或透明度叠加制造假结构 | 先归并材料与底色，再仅重建有 anchor 的阴影；不得沿量化边界直接生成路径 |
| P04 | 多个发束各有独立亮心，方向互相冲突；边缘整圈发亮 | 每块独立渐变或描边造成塑料、金属、贴纸质感 | 统一受光方向，减少至必要大块；阴影检查 owner，高光判断仍需人工 |
| P05 | 阴影跨到不属于它的皮肤、发束或透明区；发缝出现浅色漏缝 | 遮挡顺序、共享边界或 clip 错误 | 使用明确的接收面与合法遮挡；检查 owner mask 外像素及多尺寸边界 |
| P06 | 把所有颜色变化删掉，靠几块互不相干的贴片保留层次 | 将 flat color 误解为无形体关系，反而丢失发流 | 保留相邻色块边界、必要遮挡阴影与获准的低频色调变化 |
| P07 | 为了掩盖色场缺陷而加 blur、颗粒、光晕或高密度路径 | 模糊或复杂度隐藏错误，没有修复来源 | 回到材料面重画；不得把滤镜或路径数量作为细腻程度的证据 |

硬质饰件允许形体确实存在的平面转折；尖角本身不是 P02。问题是亮暗边界是否对应实际材料与形体。高光、gradient、曲线数量都不能脱离上下文单独判好坏。

## 提示词中的有效约束

将以下说明放入生产 prompt 的 Aikon 覆盖和验收段，保留各 profile 真实差异；源译文保持原样。不是只堆叠“干净、极简、高质量”等形容词。

**short 的上色说明模板**：

> 保留本轮锁定的轮廓、可见脸域、眼位与装饰连接。按真实材料组织大色面；发束靠真实边界、遮挡和宽缓受光区分。高光按参考取舍，允许顺形连续色场；若一维渐变会把立体起伏削平，可用少量宽解析场表达同一受光关系。不要复制参考位图中的颗粒、斑驳、自动量化碎片或无形体依据的亮片。检查未采样尖端的色域，不让渐变外推成新亮针。眼睛可以有微弱暗色色场及细边光泽，腮红保持简单。

**full 的上色说明模板**：

> 先列出材料底色及发束的覆盖关系，再绘制 paint。每条阴影必须有 receiver 和遮挡/转面 anchor；整体采用底色加约一档宽弱阴影，避免透明暗片相互叠加。高光可不画；必要时全头仅保留一到两个顺着主要发面的大高光，并遵循同一受光方向。不把每个发束独立做成带亮心的渐变胶囊。允许参考有依据的平滑低频过渡，禁止云纹、颗粒、孤立多尖亮斑和伪金属切面。不能为了清理上色改变已锁定 geometry。

真正的 prompt 测试必须先把实际提示词及参考交给绘制 Agent，再获取其产物。先写完 SVG、之后补一份 prompt 说明，不构成提示词效果验证。

清理任务还应明确：删除无依据paint后，参考中仍重要的发束分组不得无声消失。若当前geometry缺少这些分组，输出应标为“paint改善、geometry仍不足”，并记录下一版需要重建的材料边界；不以“零高光、低噪声”宣布整张完成。

## 自动检查与视觉检查的分工

自动检查必须报告实际实施的项目；没有实现的检查不可标 passed。直接手写 SVG 与 scene/helper 路径执行相同的最终产物检查，不能以绕过 helper 逃过约束，也不能把 helper 的子集限制说成 SVG 天生不支持 gradient。

可自动阻止：内嵌位图与外部资源、纹理/filter/pattern 等禁用构造、缺少材料归属的 paint、超出已声明数量或色阶预算、gradient 反复跳色、阴影漏出 owner、非预期 alpha 缺口，以及 geometry freeze 被违反。眼内虹膜/白点与合法暗色色场须区分，不能仅因颜色不唯一拒绝自然眼缘。数量和颜色预算须来自当前明确的合同，不编造“官方阈值”。

像素检查使用实际 SVG 的固定版本渲染结果，而非只检查源文本。为每个材料面渲染同坐标 owner mask，在内部腐蚀掉抗锯齿边缘、合法遮挡边界和已声明的色块边界，再分别检测纯色偏差或相对已声明 gradient 的残差。不能用全图 RGB 唯一颜色数或全图相邻像素差作为纹理门槛：抗锯齿、渐变、不同材料都会产生正常色差。边界另测漏缝和光晕，不能在内部分析时排除之后就永远不检。

至少查看原尺寸、目标头像尺寸，以及同一裁切在深浅展示底上的结果。高分辨率用于发现内部斑驳与尖碎亮片，小尺寸用于判断主要层次是否仍清楚；展示底不写进透明 SVG。所有阈值须记录尺寸、单位、区域、渲染器与边界容差，先对已知好例和注入缺陷验证。

仍须实际视觉判断：明暗是否顺形、光向是否可信、曲线是否自然、参考身份是否保留、色块是否像贴片，以及整体是否接近用户认可的风格。一个有 owner、两色、无 noise 的星形亮斑仍可通过部分机器检查，却应被视觉拒绝。最终状态分别记录 `structure`、`paint_pixels`、`visual_review` 和 `user_acceptance`；机器检查通过不推进最后两项。
