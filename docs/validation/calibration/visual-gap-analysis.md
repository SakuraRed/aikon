## 2. 观察：参考的几何关系与结果的具体差距

### 2.1 “圆润脸”在参考中是被头发塑形的脸部区域

**参考观察。** r1 的中央长刘海、画面右侧包住脸的鬓发、左侧斜向发缘共同围出一个宽而偏斜的皮肤区域。下方脸颊向下颌过渡后变得较平缓，临近底边仍能读出下颌转向；头部外轮廓与皮肤轮廓不是同一个圆。r2 的脸底部是一段宽而浅的弧，右侧沿脸颊收回到下颌，再由浅蓝侧发接住；顶部“圆”的印象主要由帽缘和头发外壳形成。short-black 的下颌也有较平缓的底部，左右侧分别被直落长发和内弯鬓发压住。full-teal 的右颊、下颌和耳前发束是三条不同的边界，耳朵位于侧发后方。

**结果观察。** review-2 男管理员及 review-3 Aria 的脸都有连续、近似卵形的外侧弧；下方很大一片皮肤直接被画布截断，下颌的转向与下部收束几乎不可读。review-1 立绘和 Sunna 虽然增加了尖发束，皮肤仍像先放好的一张大脸模，头发附着在它上面。使用自定义 path 并没有改变这种视觉结果：侧颊、下颌和额侧的曲率缺少明确分工。

**造成的差距。** 参考中的可爱感来自饱满颊部、宽而柔和的下颌、被刘海压缩的额区及不对称鬓发。结果把这些关系压缩成了“足够圆、足够大、左下出框”。人物换了发色，脸部空间的组织仍很相似。用户所说的“过于绝对圆头”对应的是这种可见形态，而不取决于源代码有没有使用 `ellipse`。

### 2.2 近景构图需要同时安排头发外壳、皮肤开口和附件

**参考观察。** r1 的头发和褶边连续包覆上方及右侧，脸从这层外壳中探出；发顶翘束是头发流向的延续，侧蝴蝶结压在外侧后发上。r2 的帽子、帽缘、额发和右侧后发形成连续叠压；右上留白沿主体轮廓展开。short-pink/blue 中，发顶弧线、刘海尖端、右鬓发回钩和底部脸缘共同决定放大尺度，不能只把脸单独放大。

**结果观察。** review-1 立绘的珊瑚粉簇在顶边被切成一团显眼的花状贴片，青绿环在右上近乎独立悬放；两者与黑发根部之间的关系弱。review-3 人形 Aria 的天线形成两根突出的裸杆，画面左侧一根被顶边直接截断，基座几乎没有进入头部结构；右侧束发变成远离主脸的一条波状尾巴。review-2 女管理员的头顶成为厚而完整的圆帽状块，长侧发向下直接离开画布。

**造成的差距。** 各项附件分别“存在”，但没有一起参与头部轮廓的设计。我们裁切的是一个装好零件的头像，参考则把裁切本身用于组织主体。右上有空白、下巴在框外，均不能单独证明近景关系与参考一致。

### 2.3 眼睛的规则被执行成孤立的几何常数

**参考观察。** r1 的胶囊更饱满，圆端存在感强，接近实心长圆形；r2 的眼睛更修长，仍有宽厚、圆滑的端部。short-black 进一步呈现较纤细的胶囊；short-pink/blue 与 r1 的视觉重量也不完全相同。它们属于同类眼形，但实际样例并不是一个未经比较就可共用的精确圆角矩形。各图眼睛都处在刘海与双颊共同围出的面部空间内：眼顶与发尖的距离、外侧眼缘与鬓发的距离、眼底到下颌的余量相互配合。

**结果观察。** review-3 Aria 两形态的眼睛表现为很长、笔直且端部半径恒定的黑条；对照 r1，黑条的长度感更强。review-2 的眼睛则较细，落在开阔的浅色脸面上，和头部装备之间的联系很弱。review-1 立绘的眼睛、腮红与发尖也像逐项放入：两眼都可见，但眼对的位置没有反过来约束额发缺口、颊部宽度和下颌形态。

**造成的差距。** “两眼等大、平行”约束的是同一张图内的关系；原文没有要求所有 IP 共用眼睛坐标、眼距和脸部占比。仅凭 3:1 或 2.5–3:1 的数值，并不能得到参考的视觉重量。r1 与短版文字比例之间可能存在图文差异，应分别记录并等待实际测量，不能凭这次目视宣布某个统一比例已由参考证明。也不能只因某个样例饱满，就把所有眼睛改成圆点。

## 4. 原因判断

1. **校准对象缺失。** 我们先把文字转为统一参数，再展开不同主体。没有先用一张实际立绘证明“主体轮廓经过 bot 化仍可辨认、风格与 r1/r2 接近”。所以共享的脸部组织、发片写法和裁切问题被批量带入 14 张图。
2. **观察停在名词层。** 身份笔记写出了发色、马尾、发夹、天线、面罩，却没有记录这些形状从哪里长出、压住谁、朝哪里回转。后续路径只满足清单，未重建关系。
3. **几何规则替代了绘画判断。** 胶囊比例、旋转角度、无口鼻和出框容易检验，成为实际工作中心；脸的可见形态、发型整体包围范围、关键阴影位置未获得同等校准。
4. **分支创作缺少有效控制。** 通过改色、角度、添加高光和小部件制造 short/full 差异，无法暴露共享造型是否正确。两个分支都以同一未校准轮廓为基础，不能互相印证。

这些原因解释失败路径，不改变用户拒绝结果的状态。

## 5. 只用 img_1 单主体进行可对照的校准

### 5.1 校准对象和证据分工

选 `img_1.png` 中的单一人物作为校准重点：用户直接提供了完整立绘，不涉及管理员面罩冲突或 Aria 双形态选择；头部包含黑发、两侧珊瑚粉簇和青绿环，足以检验轮廓、颜色、附件层次是否同时保留。暂不推测角色名字或粉簇的材质。

r1 用于主要观察脸部空间、鬓发包覆和近景层次；r2 用于核对宽下颌、眼睛与额发的距离以及附件包住头部的方式。short-black 提供深色发片的局部层次参照。不要把这些图的发型、帽子或褶边移植进主体。

### 5.2 先建立关系，再确定参数

后续单主体对照应先画清并标记以下关系，记录“原图观察”与“bot 化调整”各是什么；本轮仅列策略，不生成这些图。

- **外轮廓**：黑发的发顶最高处、分缝方向、左右鬓发结束位置；珊瑚粉簇的两个根部、各自最大体积和末端方向；青绿环在头后经过哪些区域、哪段被头部挡住。它们共同组成头像边缘，不能分别贴上去。
- **可见脸形**：刘海压住额区的斜线、侧发与两颊相接的拐点、较宽下颌的转向，以及左/下边框实际穿过的位置。先检查脸的宽窄与收束，再落眼睛。
- **眼对**：在可见脸部内一起决定两眼尺度、间隔和高度，随后维持同尺寸/同角度；对照眼顶到发缘、眼外侧到鬓发、眼底到颊/下颌的空隙。不再直接继承 Aria 或 Sunna 的绝对坐标。
- **发块质量**：黑刘海应保留原图的偏置流向；各束具有不同的宽根、收尖位置和回转。珊瑚粉簇需保留内部卷向与根部压叠，避免重复等大圆瓣。青绿环保留可读的平面与前后厚度变化，避免只剩一个均匀描边椭圆。
- **有限层次**：只在前刘海压后发、粉簇扎束根部、侧发转入颊后的地方考虑阴影；高光跟随体积弯折。先去掉无造型依据的装饰光条，不用增添细节补轮廓问题。

### 5.3 对照顺序与停止条件

1. **轮廓对照**：先把原立绘头部与拟定头像的发顶、鬓发、粉簇和环的相对布局放在同一观察页。检视者应能逐项指出保留了什么、为了眼睛和裁切改了什么；写不清的关系继续研究，不扩大主体数量。
2. **脸部对照**：将候选和 r1/r2 在相同显示尺寸、相同展示底下比较皮肤开口、下颌转向、刘海落点与眼对重量。展示底只消除比较干扰，透明输出要求不变。像素测量可补充比例证据，不能自动决定视觉结果。
3. **有限色块对照**：检视黑发/粉簇/青绿环是否由形态就能对应原立绘，配色是否帮助分层。若必须靠标题或颜色解释身份，返回轮廓关系，不继续加发夹等细节。
4. **同主体 short/full**：每轮仍保留用户要求的两份，但只覆盖这一主体。先列出两份源提示词的真实差异；不为了让 full “看起来更完整”而添加任意零件，不以两版互相接近证明风格正确。
5. **真实反馈后推进**：以用户对该单主体的反馈决定下一次有界修正。未解决脸形、发型或附件关系时，不重开其余主体批量制作；不把用户未答状态记作接受。
