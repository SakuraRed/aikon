r1 两眼主轴约 104.389° / 101.753°，旧 short 约 104.007° / 104.004°，角度均从原图 x 正方向顺时针计量。旋转相近而轮廓不同，证明单独检查 `rotate(14)` 会漏检眼形错误。r1 眼线斜率约 19.428°，旧 short 为 17.475°；这些只是二维测量，**不表示已经估计或修复仰头 pitch**。

## 算法与固定规则

1. 读取二维 coverage mask。检查连通分量、破洞、裁切、分辨率及复杂度。少于 16 像素的眼宽返回 `not_assessed`，不会凭放大后的像素给出合格结论。
2. 从 coverage = 0.5 的水平／垂直相邻像素交点提取亚像素轮廓。PCA 得到初始主轴；原图中心、原始宽高、角度与画布归一化尺寸全部保留。
3. 同时拟合两个形状族。胶囊使用到线段端点圆的精确有符号距离；椭圆使用隐式方程除以梯度范数的一阶几何距离。两者有各自中心、角度和尺寸参数，使用相同原始眼宽归一化误差。
4. 冻结胶囊 RMS <= 2% 眼宽、P95 <= 4% 眼宽。若胶囊误差已超过 0.8%，且椭圆误差不到其 55%，标记 `ellipse_explains_contour_better`。长宽比范围 1.45–4 仅为当前长胶囊合同，不代替某一角色的确切比例要求。
5. 保存 19 个主轴位置的宽度剖面、两模型误差，以及双眼中心向量、间距、眼线角、轴角差和两眼尺寸比。没有独立移动、拉伸两眼后再声称匹配。

上述形状规则在真实 r1 / 旧图检查前确定；首轮 16 个解析控制和真实样本均给出同一分离结论。之后独立 Pillow 正例发现新增的“远端淡像素”保护误报 Lanczos3 正常边缘采样：原一像素邻域只适合覆盖抗锯齿，不够容纳三像素采样核。修正为三像素方形边界邻域；**没有更改轮廓 RMS、P95 或椭圆优势阈值**。远离轮廓的半透明杂点仍通过专门负例捕获，不让它改变 PCA 主轴。

## API 与 CLI

运行依赖沿用仓库的可选质量验证环境，不为分发 Skill 添加强制依赖。

```python
from tools.analyze_capsule_geometry import analyze_eye_mask, analyze_pair

report = analyze_eye_mask(mask)  # bool 或 [0,1] float 的二维 coverage
pair = analyze_pair([left_mask, right_mask])  # 同一原图坐标系与画布
```

API 调用者负责外层时限。CLI 自带现有 `run_bounded` 的 50 秒进程树时限：

```text
python -B tools/analyze_capsule_geometry.py --mask eye-mask.png --output <evidence>
python -B tools/analyze_capsule_geometry.py --study --output <evidence>
```

单 mask 模式返回 0 表示该轮廓未触发规则；2 表示失败或无法判断。`--study` 返回 0 表示正例、负例和真实回归均符合预期，不表示负例作品合格。`summary.json` 显式输出 `control_suite_pass`；旧作品的 `quality` 为 `rejected_by_user`，其眼形仍是 `fail`。控制预期变化时返回 2；进程超时返回 124。标准输出仅一条小 JSON 摘要。

## 验证边界

- 本地新增的 17 项测试通过，包括真实 r1 / 旧图、独立抗锯齿控制、错误端帽、低分辨率、破洞、裁切和复杂轮廓；未重复执行整个仓库测试。
- 没有声称测得“99% 相似”、修复姿态、鲸鱼身份或光泽。胶囊判定只是形状合同中的一个方面。
- 默认侧边平行、端帽近圆。强透视扭曲、极端不对称或遮挡眼部可能失败；需先明示对应设计合同，不能为某个候选临时调宽门槛。
- r1 的暗色阈值提取是该明确参考的人工复查流程，不是通用眼部检测器。彩色眼睛、眼镜或面罩不能直接复用此阈值；可以提供可信的独立眼 mask，仍保留提取依据。
- “未触发规则”不证明肉眼自然；需要结合原图、轮廓证据和用户审计。
