# Skill 创建与验证循环

本文件规定待执行流程，不是已完成测试的报告。产品分支以真实访谈结果为准。

## 创建前

1. 完成来源调查和实际参考图查看，记录正例、辅助例、反例及未验证范围。
2. 用真实用户回答收敛视觉取舍、交互与分发边界；工程细节由 Agent 在范围内处理。
3. 分发资源与私有研究资料分开，技能入口使用相对路径，不依赖本机工具或账号。

## 单次迭代

创建最小可用技能 → 检查包结构和资源引用 → 独立 Agent 按真实输入完成创作/修改 → 检查 SVG 结构 → 实际渲染与查看 → 用户或独立评审反馈 → 只修复已观察到的问题 → 重跑受影响场景。

每次保留输入约束、执行环境、生成 SVG、渲染图、判断依据和未通过项。测试文件不能混进分发资源。测试资源应使用原创或已获授权的主体。

## 首批必要检查

| 层次 | 能证明的事项 | 不能证明的事项 |
| --- | --- | --- |
| 包结构 | frontmatter、相对资源、无占位模板、无本机路径 | 模型会正确执行 |
| 行为 | 分清风格/主体，正确提问，未答不代答，遵守指定目录和局部修改 | 最终图一定好看 |
| SVG | 可解析、真实矢量、自包含、无脚本/远程资源/位图包装 | 风格符合目标 |
| 渲染 | 实际看到层级、裁切、眼部、24/48/128 px 可读性 | 主体身份被用户认可 |
| 修改回归 | 修改区域与约束一致，未要求变化处没有无故重画 | 任意编辑均可保证像素不变 |
| 跨环境 | 特定 harness/模型/版本上的实际结果 | 所有模型和未来版本兼容 |

不能把同一模型的多个子 Agent 当作多个基底模型。跨模型验证未执行时明确保留待验。

## 停止条件

单轮修复达到本轮约束即停止重复测试；同一故障两次无进展则回到原因分析。剩余问题需要用户偏好或缺失能力时保留问题及证据，不伪造完成。反馈导致设计方向变化时更新约束，再建立新版本。
